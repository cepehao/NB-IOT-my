# Пробные правила адаптивного управления

## Статус

Автоматический цикл подключён к симулятору: при Adaptive-P или Adaptive-RA/DT он использует закрытое окно наблюдений раз в 500 мс, получает прогноз и применяет допустимое действие. Короткая проверка прошла на одном устройстве и тестовой development-модели. Запуск требует явно передать модель; development-модель разрешена только в локальном профиле разработки. Правила ниже — предварительная настройка: они не подобраны по реальным данным и не подтверждают улучшение сети.

## Правила для коротких development-проверок

Прогноз — оценка среднего числа RA-устройств `meanRaUe`. В начале запуска прошлого закрытого окна нет, поэтому действие не выбирается. Дальше решение разрешено только на границе окна в 500 мс, когда конец окна наблюдений совпадает с текущим временем. Просроченный, отсутствующий или недопустимый прогноз оставляет настройки без изменения. На последнем моменте горизонта действие не применяется.

Для **Adaptive-P** меняется только вероятность доступа `P`; доля ресурсов остаётся RA/DT = 10/90:

| Прогноз `meanRaUe` | P |
|---:|---:|
| до 1 включительно | 1 |
| больше 1, до 3 | 0,75 |
| больше 3, до 6 | 0,5 |
| больше 6, до 10 | 0,25 |
| больше 10 | 0,1 |

Для **Adaptive-RA/DT** вероятность доступа остаётся `P=1`; меняется только доля ресурсов:

| Прогноз `meanRaUe` | RA/DT |
|---:|---:|
| до 1 включительно | 10/90 |
| больше 1, до 5 | 20/80 |
| больше 5 | 30/70 |

Это пробные пороги из `configs/adaptiveDefaults.m`, а не требование ТЗ и не рекомендованные значения для реальной сети. Их можно пересматривать только по независимым development/validation данным; финальная группа остаётся закрытой до фиксации правил.

## Защита применения

Изменение принимается только в текущий момент решения и на границе окна. Поддерживаются `P` из набора 0,1/0,25/0,5/0,75/1 и доли RA 10/20/30%. Базовая конфигурация Static не переписывается: действие хранится отдельно. При смене доли календарь сначала проверяет, укладываются ли уже назначенные ресурсы в новые квоты. Если нет — всё действие отклоняется без частичного изменения; прошлые назначения не отменяются.

В результате сохраняются признаки окна, прогноз, предложенные и применённые настройки, причины отказа и показатели числа решений/переключений. Adaptive-запуски получают схему результата 3 и отдельный `*_controller.csv` со схемой журнала 1; файл перечислен и проверяется в `case-complete.json`. Эффективные правила сохраняются в MAT и описании запуска, а их хеш входит в ID случая. Имена Adaptive-файлов отличаются от Static; повторная запись того же Adaptive-случая отклоняется.

Проверены оба режима, отсутствие модели, недопустимый прогноз, конфликт квот, запись и чтение таблицы контроллера и различие ID при изменении правил. Это проверка работы кода, а не качества модели или полезности управления. Для рабочего использования нужны реальные независимые данные, оценённая модель и внешнее сравнение режимов.
