# Инструкция для внешнего компьютера

Этот комплект переносит код, исходные данные, бюджет и журнал этапов. Само распаковывание не разрешает вычисления. Запускайте этапы только после отдельного согласования с преподавателем и проверки ресурсов внешнего компьютера.

Для команд ниже требуется PowerShell 7.5 или новее (`pwsh`). В этой версии есть режим `ConvertFrom-Json -DateKind String`, который сохраняет UTC-времена из журнала как строки; более ранний PowerShell может преобразовать их в локальное время. Проверьте версию командой `$PSVersionTable.PSVersion`.

## 1. Проверить комплект

Распакуйте папку в короткий путь без синхронизации с облаком. В PowerShell выполните процессные проверки комплекта:

```powershell
pwsh -NoProfile -File "<ПАПКА-КОМПЛЕКТА>\project\verification\external\testExternalStages.ps1"
```

Эти проверки используют заглушки и не запускают MATLAB. Затем откройте `manifest.json` и убедитесь, что бюджет заполнен данными этого компьютера: `targetMachine`, `availableMemoryBytes`, `maxUE`, `maxCaseSeconds`, `maxSuiteSeconds`, `maxProcesses`. До `pilot` ответственный за внешний компьютер проверяет эти ограничения и подтверждает их статусом `target-reviewed`; исходное `provided-but-requires-target-review` блокирует вычислительные этапы. Не переносите лимиты с другой машины.

## 2. Посмотреть команду без запуска этапа

По умолчанию команда только показывает состояние и безопасную точку входа. Она не запускает MATLAB, не создаёт процесс, не меняет `stages.json` и не резервирует ID:

```powershell
pwsh -NoProfile -File "<ПАПКА-КОМПЛЕКТА>\project\verification\external\runExternalStages.ps1" `
  -PackageFolder "<ПАПКА-КОМПЛЕКТА>" -Stage validate -Inspect
```

Доступные этапы: `validate`, `pilot`, `data`, `assemble`, `train`, `freeze`, `evaluate`, `admit`, `compare`, `summarize`. Один вызов с `-Execute` относится только к одному этапу. Следующий этап запускайте отдельной командой после проверки отчёта предыдущего.

## 3. Запуск после согласования

Для любого вычислительного этапа указывайте внешний профиль и явный бюджет в манифесте:

```powershell
pwsh -NoProfile -File "<ПАПКА-КОМПЛЕКТА>\project\verification\external\runExternalStages.ps1" `
  -PackageFolder "<ПАПКА-КОМПЛЕКТА>" -Stage validate `
  -ExecutionProfile external-machine -Execute
```

`validate` проверяет исходники и готовность пакета. Для допуска пилота нужны свежие Stage 2 targeted и physical проверки и отдельная техническая приёмка. Если такой файл ещё не создан, этап останется в состоянии `awaiting-review`; пилот не запустится.

`pilot` запускает полный фиксированный набор `[100 500 1000 2500 5000]`. Для него `maxUE` должен покрывать 5000, а в комплекте должна быть отдельная запись согласования преподавателя. Не повышайте лимит до 5000 без такого согласования. До его получения задайте путь к записи при создании комплекта:

```matlab
options.stageOptions.pilot = struct( ...
    'pilot5000ApprovalFile', 'reviews/pilot-5000-approval.json');
manifest = prepareExternalRun(options);
```

После проверки бюджета и его статуса `target-reviewed` посмотрите область согласования без запуска:

```powershell
pwsh -NoProfile -File "<ПАПКА-КОМПЛЕКТА>\project\verification\external\runExternalStages.ps1" `
  -PackageFolder "<ПАПКА-КОМПЛЕКТА>" -Stage pilot -Inspect
```

Команда печатает `EXTERNAL_STAGE_PILOT5000_SCOPE_DIGEST`. Передайте преподавателю этот digest и параметры компьютера. Только после фактического ответа поместите в указанный файл запись такого вида:

```json
{
  "schemaVersion": 1,
  "decision": "approved",
  "authority": "professor",
  "reviewer": "Имя преподавателя",
  "reviewedAtUtc": "2026-10-19T12:00:00Z",
  "scopeDigest": "<digest из inspect>",
  "recordReference": "Ссылка или точное название записи решения"
}
```

Заполните дату и ссылку по реальному решению. Digest привязан к хэшу кода комплекта, пяти фиксированным уровням нагрузки, компьютеру и всем лимитам бюджета. Если код или любой лимит изменился, согласуйте новый digest. Перед запуском контроллер пересчитывает общий хэш списка кода и отдельно сверяет байты каждого упакованного файла. Несовпадение блокирует этап до изменения журнала и резервирования ID. Контроллер также блокирует отсутствующую, отклонённую или относящуюся к другой области запись; хэш записи входит во входы этапа. При замене решения сохраните старую запись в истории комплекта; новая должна соответствовать текущему scope digest.

Перед каждым этапом, зависящим от пилота, контроллер заново сверяет текущий файл согласования с завершённым отчётом. Это относится и к косвенным зависимостям: например, `compare` и `summarize` проверяют актуальность пилота через всю цепочку. Если согласование изменили, отозвали, удалили или не удалось проверить, `pilot` получает состояние `stale`, а новый этап останавливается до создания папки попытки и выделения ID. Получите актуальное согласование и заново выполните `pilot`; старую запись в `stages.json` вручную не сбрасывайте.

Контроллер выборочно измеряет суммарный working set процессов пилота (объём памяти, закреплённый за работающими процессами), число процессов и время всего запуска. Если на любом этапе число процессов выше `maxProcesses`, процессный job останавливается. `data` и `compare` требуют завершённый отчёт пилота с измерениями памяти, числа процессов и времени, явный бюджет и подтверждённый статус ресурсов (`target-reviewed` или `measured-and-target-reviewed`). Если измерения требуют изменить бюджет, сохраните новый бюджет и его review; изменившиеся входы делают прежний pilot устаревшим. Распределение ID берётся из пакета; реестр изменяется только после явной команды `-Execute` и успешной предварительной проверки.

Этапы `assemble`, `train`, `freeze`, `evaluate`, `admit`, `compare` и `summarize` используют явно подготовленные параметры в `stages.json`. Пути в параметрах задаются относительно комплекта. Если параметров или согласованного протокола нет, этап остановится и попросит дополнить комплект; значения по умолчанию не выдумываются.

Параметры задаются при подготовке пакета в `options.stageOptions`; `prepareExternalRun` переносит их в конфигурации соответствующих этапов в `stages.json`. Например, группы данных нужно назначить заранее, с точными ID из `idAssignments`:

```matlab
options.stageOptions.data = struct( ...
    'counts', [100 500], ...
    'burstDurations', [100 500], ...
    'groups', [ ...
        struct('role', 'training', 'split', 'train', 'realizationIds', [1500 1501]), ...
        struct('role', 'validation', 'split', 'validation', 'realizationIds', [1502]), ...
        struct('role', 'model-test', 'split', 'test', 'realizationIds', [1503])]);
manifest = prepareExternalRun(options);
```

Числа и ID в примере — только форма записи. Используйте значения, выделенные для конкретного пакета и согласованные в матрице эксперимента.

Для `admit` укажите файл человеческой научной оценки:

```powershell
pwsh -NoProfile -File "<ПАПКА-КОМПЛЕКТА>\project\verification\external\runExternalStages.ps1" `
  -PackageFolder "<ПАПКА-КОМПЛЕКТА>" -Stage admit `
  -ReviewFile "<ПАПКА-КОМПЛЕКТА>\<ФАЙЛ-ОЦЕНКИ>" `
  -ExecutionProfile external-machine -Execute
```

Путь и хэш файла оценки сохраняются в конфигурации этапа `admit`. Перед `compare` и `summarize` контроллер сверяет текущую оценку с завершённым отчётом допуска. Если файл изменили, решение отозвали, файл пропал или его нельзя проверить, этап `admit` помечается `stale`, а сравнение останавливается до запуска и выделения ID. Для новой оценки сначала повторите `admit` с актуальным `-ReviewFile`; сравнение разрешено только при завершённом отчёте с `modelAcceptanceStatus=accepted`.

Приёмка не выполняется автоматически после оценки. Fixture-данные и учебные модели не могут получить научный допуск; сравнение также требует принятой модели.

Во время `admit` dispatcher копирует каталог candidate вместе со всеми его evidence в `stage-results/admit/<digest>/results/candidate-package`. Publisher записывает `model-acceptance.json` рядом с этой копией только после проверки отдельной человеческой оценки и научных условий. Исходный candidate-пакет не изменяется. При отказе допуска acceptance и завершённый stage report не создаются; сохранённую копию ошибочной попытки можно использовать для диагностики.

## 4. Отчёты, остановка и повторный запуск

Для каждого запуска сохраняются `stage-report.json`, журналы процесса и файлы результата в `stage-results/<этап>/<digest-входов>/`. Не заменяйте и не удаляйте старые каталоги. Отчёт с `status=complete` и совпадающими SHA-256 — обязательный маркер завершения; одного кода выхода 0 недостаточно.

Нажатие Ctrl+C останавливает принадлежащий запуску процессный job и его дочерние процессы. После обычного завершения с ошибкой этап можно запустить снова отдельной командой. Повтор успешно завершённого этапа с теми же входами будет no-op. Изменение входов пометит прежний результат как устаревший и сохранит его; новый запуск получит отдельную папку.

Если после аварийного закрытия состояние осталось `running`, не редактируйте `stages.json` вручную. Контроллер сохраняет PID и время старта владельца и дочерних процессов. Сначала убедитесь, что процессы из этой записи завершены, затем выполните сверку состояния:

```powershell
pwsh -NoProfile -File "<ПАПКА-КОМПЛЕКТА>\project\verification\external\runExternalStages.ps1" `
  -PackageFolder "<ПАПКА-КОМПЛЕКТА>" -Stage pilot -RecoverInterrupted
```

Укажите вместо `pilot` фактически прерванный этап. Команда не запускает MATLAB: она разрешает отдельный повтор только если временные метки владельца и дочерних процессов корректно разбираются как UTC, проверка PID подтверждает их завершение, нет другого выполняющегося этапа, а хэш реестра ID совпадает с хэшем на входе прерванного этапа. Ошибка или неопределённый результат проверки PID блокирует восстановление без изменения журнала. При успешной сверке команда помечает старую попытку как `failed`, снимает запись владельца и оставляет её файлы и реестр без изменений. После сообщения `EXTERNAL_STAGE_INTERRUPTED_RECONCILED` проверьте сохранённую папку попытки и запускайте этап отдельной командой `-Execute`; новая попытка получит отдельную папку.

Если процесс ещё работает, запись владельца неполная или хэш реестра изменился, контроллер ничего не исправляет и блокирует повтор. Сохраните комплект и передайте координатору для сверки занятых ID и неполного результата. Не меняйте реестр и не повторяйте этап в этом комплекте до завершения такой сверки. Незавершённый результат без достоверного отчёта не считается завершённым.

## 5. Что вернуть преподавателю

Передайте комплект целиком вместе с обновлённым `manifest.json`, `stages.json`, `stage-results/`, копией исходного `realizationRegistry.json` и журналом изменений. Сохраните Stage 2 targeted log, physical report и техническую оценку; пилотный `load-pilot.csv`/`.mat` и подтверждение ресурсов; результаты и split-manifest этапа данных; dataset и его `artifacts.json`; training manifest и модели; freeze/evaluation/acceptance records; сравнение, summary и финальный acceptance report. Не передавайте учётные данные и файлы вне списка проекта.
