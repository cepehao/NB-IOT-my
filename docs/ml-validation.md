# Четыре модели прогноза нагрузки

## Что уже проверено

В проект добавлены четыре способа оценить среднее число устройств в очереди базовой станции по её предыдущим показателям:

- **Линейная регрессия** — ищет простую прямую зависимость между показателями и нагрузкой.
- **Дерево решений** — строит понятные правила вида «если показатель выше порога, то…».
- **Случайный лес** — усредняет прогнозы многих деревьев, чтобы уменьшить зависимость от одного набора правил.
- **Градиентный бустинг** — строит деревья по очереди, каждое старается исправить ошибки предыдущих.

MATLAB R2025b и Statistics and Machine Learning Toolbox найдены; лицензия доступна. Все четыре метода обучились на маленькой искусственной таблице с разными ID и группами `train`, `validation`, `test`. Тесты проверили сохранение, повторную загрузку, одинаковость прогноза, порядок признаков и защиту от пересечения ID между группами.

Для обучения требуется текущая версия признаков `bs-known-v2.0`. Старые сохранённые таблицы `static-v1.0` можно читать отдельно, но их недостаточно для обучения этих моделей: новые признаки не подставляются автоматически.

Для научного набора `candidate-training` сама функция обучения повторно проверяет, что роли `training`/`validation`/`model-test` заданы явно, совпадают с группами строк и таблицей ID в manifest. Роль `final-comparison` отвергается до подгонки моделей, даже если вызвать функцию напрямую. Это защищает итоговое сравнение от подбора модели.

Это проверка того, что программная цепочка запускается. Искусственная таблица не показывает, какая модель лучше работает в сети. Пакеты имеют отметку `development`; ни одна модель пока не принята для адаптивного управления.

## Как устроена проверка

Разные внешние ID разделяются между тремя группами. Окна одного ID всегда остаются в одной группе, чтобы модель не могла увидеть почти тот же сценарий при обучении и проверке. Заполнение пропусков и масштабирование показателей рассчитываются только по группе обучения. В качестве простого ориентира отчёт также считает прогноз, равный среднему значению группы обучения.

Для каждого способа и каждой группы отчёт содержит среднюю абсолютную ошибку (MAE), корень средней квадратичной ошибки (RMSE), среднее смещение прогноза, число окон и ID, а также время прогноза. Предварительный выбор модели использует только MAE на validation. Результат test не участвует в выборе.

## Запуск на подходящем сохранённом датасете

Для обучения нужен готовый файл `dataset.mat`, внутри которого есть переменная `data`, а в ней — отдельные группы `train`, `validation` и `test`. Каждая группа должна содержать свои независимые ID. Подойдёт только проверенный набор с ролью `candidate-training`; маленькие искусственные данные из теста используются автоматически самим тестом. Сохранённый пилот с одним ID 1064 для реальной проверки моделей не подходит.

В MATLAB из корня проекта:

```matlab
setupProject();
options = struct( ...
    'datasetFile', fullfile(pwd, 'results', 'datasets', 'eligible', 'dataset.mat'), ...
    'outputFolder', fullfile(pwd, 'results', 'models', 'first-candidate-run'));
[models, report] = trainLoadModels(options);
disp(report.metrics);
```

Путь в примере нужно заменить на существующий подходящий датасет. Команда читает только явно выбранный MAT-файл и переменную `data`; автоматического поиска данных нет. Папка результатов должна быть новой или пустой.

В папке результатов появятся четыре пакета модели, отдельные JSON-файлы с проверочными суммами, `metrics.csv`, `training-manifest.json` и `training-report.mat`. Ошибка или неподходящие данные должны быть исправлены до повторного запуска; непустая папка не перезаписывается.
