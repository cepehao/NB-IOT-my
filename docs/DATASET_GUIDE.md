## 1. Что мы моделируем (за 5 минут)

**NB-IoT** (Narrowband Internet of Things) — стандарт мобильной связи (часть LTE/4G) для простых
устройств: счётчиков воды и электричества, датчиков, трекеров. Они передают редко и мало (у нас —
пакет 200 байт), зато их очень много на одну базовую станцию — сотни и тысячи.

Картина, которую моделирует симулятор:

```
        ┌─────────────── сота, радиус 1 км ───────────────┐
        │   📟  📟        📟         📟      📟            │
        │        📟    📡 базовая станция (BS)   📟        │
        │   📟       📟        📟     📟         📟        │
        └────────────────────────────────────────────────┘
          📟 = устройство (UE, User Equipment), их от 1 до 5000
```

**Главная проблема — случайный доступ.** Устройство большую часть времени «спит». Когда у него
появились данные, оно должно сначала «постучаться» к базовой станции и получить разрешение на передачу.
Это процедура **случайного доступа** (RA, Random Access) из четырёх сообщений:

```
 Устройство (UE)                                   Базовая станция (BS)
     │ Msg1: «я здесь» — короткий сигнал-преамбула ──▶ │  BS слышит сигнал на одной из 12 частот
     │ ◀── Msg2 (RAR): «слышу частоту №5, вот тебе     │
     │      время для следующего сообщения»            │
     │ Msg3: «я — устройство X» ─────────────────────▶ │
     │ ◀── Msg4: «устройство X, доступ разрешён»       │
     │ Данные (пакет) ───────────────────────────────▶ │  проверка CRC: дошло ли без ошибок
     │ ◀── квитанция «получено»                        │
```

Аналогия: класс, учитель задаёт вопрос, ученики тянут руку. Преамбула — это поднятая рука, но
«рук» (частот для преамбулы) всего 12. Если двое выбрали одну и ту же частоту — **коллизия**: станция
видит одну «руку», отвечает на неё, и дальше оба устройства мешают друг другу. Проигравшие ждут
случайное время (**BACKOFF**) и пробуют снова, но не больше 8 раз — потом пакет теряется.

Когда сотни устройств просыпаются одновременно (например, после отключения электричества все счётчики
разом сообщают об аварии — **массовый всплеск**, `burst`), коллизий становится очень много, и сеть
захлёбывается. Изучить это и есть цель проекта.

**Два способа помочь сети** (их сравнивает проект, ТЗ §24–26):

| Метод | Что делает | Аналогия |
|---|---|---|
| **Static** | Ничего не меняет: доля ресурсов под случайный доступ 10 %, под данные 90 % (RA/DT = 10/90) | Базовый вариант для сравнения |
| **Adaptive-P** | Если устройств много — разрешает каждому пытаться только с вероятностью P (0,1…1) | «Тянуть руку разрешено каждому второму» |
| **Adaptive-RA/DT** | Перераспределяет ресурсы: 10/90 → 20/80 → 30/70 | «Больше времени на вопросы, меньше на ответы» |

Адаптивным методам надо знать, **сколько устройств сейчас конкурирует**. Станция этого не знает
напрямую — она видит лишь косвенные признаки (сколько преамбул услышала, сколько ошибок CRC и т. п.).
Оценивать нагрузку по этим признакам будет **ML-модель**, а учиться ей нужно на **датасете**, который
собирает этот симулятор. Поэтому сценарии моделирования — основа всего проекта.

**Как симулятор считает.** Он не подставляет готовые вероятности, а моделирует настоящие радиосигналы
(waveform): формирует сигнал каждого устройства средствами LTE Toolbox, ослабляет его расстоянием
и стенами, складывает сигналы всех устройств с шумом и декодирует так, как это делала бы станция.
Поэтому результаты правдоподобны, но расчёт небыстрый (см. [§4.4](#44-сколько-это-длится)).

**Время в модели.** Один шаг — **тик = 1 мс**. Прогон по умолчанию — 5000 тиков (5 секунд жизни
соты). Каждые 500 мс (одно **окно**) станция подводит итоги — из окон и состоит датасет.

## 2. MATLAB за 15 минут

MATLAB — среда для инженерных расчётов: язык программирования плюс окно, где код пишут и запускают.
Нужен **MATLAB R2025b** с **LTE Toolbox** (дополнение для сигналов LTE/NB-IoT). Проверить, что он
есть: в командном окне набрать `ver` — в списке должна быть строка `LTE Toolbox`.

### 2.1. Окно MATLAB

| Часть окна | Зачем |
|---|---|
| **Current Folder** (слева) | Текущая папка. Перейдите в корень проекта — папку, где лежит `startupProject.m` |
| **Command Window** (внизу) | Командная строка: набрали команду — Enter — результат сразу |
| **Editor** (по центру) | Редактор файлов `.m`. Кнопка **Run** (или F5) запускает открытый скрипт |
| **Workspace** (справа) | Все переменные, которые сейчас в памяти. Двойной щелчок — посмотреть содержимое |

Ошибки печатаются красным в Command Window. Ссылка в тексте ошибки открывает строку, где она произошла.
Остановить долгий расчёт — **Ctrl+C** в Command Window.

### 2.2. Синтаксис, который встретится в сценариях

```matlab
x = 5;                  % переменная; ';' в конце — не печатать результат
x = 5                   % без ';' — MATLAB напечатает x = 5
% всё после знака процента — комментарий

v = [10 30 100];        % вектор (список чисел); v(1) — первый элемент (нумерация с 1, не с 0!)
r = 0:19;               % числа 0, 1, 2, …, 19 (запись «от:до»)
r = 0:5:20;             % 0, 5, 10, 15, 20 (запись «от:шаг:до»)

name = 'burst';         % текст в одинарных кавычках

cfg.simulation.numUE = 30;   % struct — «папка с полями»: точка обращается к полю внутри
cfg.simulation               % напечатать все поля вложенной struct

c = {};                 % cell — список, в котором могут лежать любые объекты (у нас — конфигурации)
c{end+1} = cfg;         % добавить элемент в конец (фигурные скобки!)
numel(c)                % сколько элементов

for n = [10 30]         % цикл: n по очереди равно 10, потом 30
    disp(n)             % напечатать значение
end                     % каждый for / if / function закрывается словом end

f = fullfile(pwd, 'results', 'my-run');   % путь к папке: pwd — текущая папка
```

Функции из ядра симулятора вызываются с префиксом пакета: `nbiot.config.defaultConfig()` — это
функция `defaultConfig` в папке `src/+nbiot/+config/`. Справка по любой функции: `help` и имя,
например `help nbiot.dataset.collectDataset`.

### 2.3. Скрипт

Скрипт — файл `.m` с командами, которые выполняются сверху вниз, как если бы вы набрали их в
Command Window. Создать: **Home → New Script**, сохранить под именем из латинских букв, цифр и `_`
(например, `myScenario.m`), запустить кнопкой **Run**. Имя файла не должно совпадать с именами
функций проекта и начинаться с цифры.

## 3. Первый запуск

1. Откройте MATLAB и в **Current Folder** перейдите в корень проекта (папку с `startupProject.m`).
2. В Command Window выполните:

```matlab
startupProject();     % подключает папки проекта (src, configs, examples, tests); нужно в каждом новом сеансе MATLAB
checkEnvironment();   % проверка: версия MATLAB, LTE Toolbox, файл калибровки, запись в results/
                      % (печатает таблицу найденных функций LTE Toolbox — это нормально; ошибка будет красным)
r = runSingleUe();    % пробный прогон: 1 устройство, 5 с модели, ≈ 12–20 с расчёта
```

Если всё в порядке, `runSingleUe` напечатает сводку показателей, и в ней будет `delivered: 1` —
единственное устройство доставило свой пакет. Значит, установка рабочая.

`r` — результат прогона (большая struct). Попробуйте: `r.status` (должно быть `'completed'`),
`r.kpiSummary.deliveryProbability` (доля доставленных пакетов, здесь 1).

> **Калибровка.** Для работы нужен файл `results/nprach-calibration.mat` — порог, по которому станция
> решает «услышала преамбулу или нет». Он уже лежит в репозитории; ничего делать не нужно.

## 4. Свой сценарий шаг за шагом

**Сценарий** = набор параметров одного или нескольких прогонов. Все параметры хранятся в одной
struct `cfg` (конфигурация). Рецепт всегда один: взять конфигурацию по умолчанию
(`nbiot.config.defaultConfig()` — все значения из ТЗ) и поменять только нужные поля.

**Куда класть свои скрипты.** В папку `work/` в корне проекта (создайте её). Она исключена из git:
личные сценарии не попадают в общий репозиторий. Результаты прогонов сохраняйте в `results/` — тоже
не в git.

**Первые две строки каждого скрипта** — всегда эти:

```matlab
root = fileparts(fileparts(mfilename('fullpath')));   % корень проекта (скрипт лежит в work/)
cd(root); startupProject();                          % перейти в корень и подключить проект
```

Зачем: при нажатии **Run** MATLAB может предложить перейти в папку скрипта (`work/`) — соглашайтесь
(**Change Folder**). Эти строки сами вернут текущую папку в корень проекта и подключат его, поэтому
пути вида `fullfile(pwd,'results',…)` дальше указывают куда надо. Работает, только если скрипт лежит
ровно на один уровень ниже корня (в `work/`); для другой глубины поменяйте число `fileparts`.

### 4.1. Один прогон

Создайте `work/myFirstScenario.m`:

```matlab
% ---- Мой первый сценарий: 10 устройств, массовый всплеск ----
root = fileparts(fileparts(mfilename('fullpath')));   % корень проекта (скрипт лежит в work/)
cd(root); startupProject();                          % перейти в корень и подключить проект

cfg = nbiot.config.defaultConfig();                 % все параметры по умолчанию (ТЗ)
cfg.simulation.numUE = 10;                          % 10 устройств в соте
cfg.traffic.kind = 'burst';                         % массовый всплеск: каждое UE шлёт 1 пакет...
cfg.traffic.burstStartTick = 1000;                  % ...начиная с 1-й секунды...
cfg.traffic.burstDurationTicks = 100;               % ...в случайный момент в течение 100 мс

% порог детектора преамбул (обязателен для любого прогона)
cfg = nbiot.phy.nprach.loadCalibration(cfg, fullfile(pwd,'results','nprach-calibration.mat'));

result = nbiot.runExperiment(cfg);                  % прогон: ≈ 1,5 мин для 10 UE

disp(result.status)                                 % 'completed' — прогон дошёл до конца
k = result.kpiSummary;                              % основные показатели
fprintf('Пакетов создано %d, доставлено %d (%.0f %%)\n', k.created, k.delivered, 100*k.deliveryProbability);
fprintf('Попыток доступа %d, успешных %.0f %%, с коллизией %.0f %%\n', ...
    k.raStarted, 100*k.raSuccessProbability, 100*k.collisionAttemptProbability);

nbiot.results.saveResult(result, fullfile(pwd,'results','my-first-run'));   % сохранить MAT + таблицы CSV
```

Запустите (**Run**). Через пару минут увидите числа. Затем поменяйте `numUE` на 30 и сравните:
устройств больше — коллизий больше, доставка хуже.

### 4.2. Серия прогонов и сравнение

Чтобы увидеть зависимость, прогоните несколько вариантов в цикле и сведите итоги в таблицу:

```matlab
root = fileparts(fileparts(mfilename('fullpath')));   % корень проекта (скрипт лежит в work/)
cd(root); startupProject();                          % перейти в корень и подключить проект
calib = fullfile(pwd,'results','nprach-calibration.mat');

rows = {};                                          % сюда — строки итоговой таблицы
for numUE = [5 10 20]                               % перебираем число устройств
    cfg = nbiot.config.defaultConfig();
    cfg.simulation.numUE = numUE;
    cfg = nbiot.phy.nprach.loadCalibration(cfg, calib);
    result = nbiot.runExperiment(cfg);
    k = result.kpiSummary;
    rows(end+1,:) = {numUE, k.raSuccessProbability, k.deliveryProbability, k.collisionAttemptProbability}; %#ok<SAGROW>
end
T = cell2table(rows, 'VariableNames', {'numUE','raSuccess','delivery','collision'})
```

Последняя строка без `;` — MATLAB напечатает таблицу. Её можно сохранить: `writetable(T, fullfile(pwd,'results','my-series.csv'))`.

**Важно про случайность.** Положение устройств, затухание, моменты пакетов — случайные, но
воспроизводимые: при одинаковых `cfg.simulation.seed` и `cfg.simulation.realizationId` прогон каждый
раз даёт одинаковый результат. Номер `realizationId` — это номер «мира» (расстановки устройств,
канала, трафика). Чтобы вывод не зависел от одной удачной или неудачной расстановки, повторяйте опыт
на нескольких мирах: `for id = 0:4, cfg.simulation.realizationId = id; … end` — и усредняйте.

### 4.3. Датасет для обучения

Для ML нужно много прогонов, и каждому — окна по 500 мс с признаками и правильным ответом. Для этого
есть функция `nbiot.dataset.collectDataset`: вы даёте список конфигураций, она прогоняет их все и
складывает окна в один файл `dataset.csv`. Калибровку она подключает сама.

Готовый пример — `examples/collectDatasetExample.m`; скопируйте его в `work/` и меняйте (он тоже лежит
на уровень ниже корня, первые строки подойдут). Минимальный вариант:

```matlab
root = fileparts(fileparts(mfilename('fullpath')));   % корень проекта (скрипт лежит в work/)
cd(root); startupProject();                          % перейти в корень и подключить проект
cfgs = {};                                          % список конфигураций = список прогонов
for numUE = [10 30]                                 % две нагрузки
    for id = 0:19                                   % 20 «миров» (нужно для train/validation/test, см. §7.1)
        cfg = nbiot.config.defaultConfig();
        cfg.simulation.numUE = numUE;
        cfg.simulation.realizationId = id;
        cfgs{end+1} = cfg; %#ok<SAGROW>
    end
end
summary = nbiot.dataset.collectDataset(cfgs, fullfile(pwd,'results','my-dataset'));
```

Здесь 40 прогонов. Последовательно это несколько часов (см. ниже), поэтому для первого раза возьмите
`id = 0:2` — проверить, что всё работает, — а потом запускайте полный вариант, например на ночь.

Если установлен Parallel Computing Toolbox, прогоны можно выполнять параллельно на всех ядрах:

```matlab
summary = nbiot.dataset.collectDataset(cfgs, fullfile(pwd,'results','my-dataset'), ...
    struct('useParallel', true));
```

### 4.4. Сколько это длится

Замеры на Mac (MATLAB R2025b, M4 Pro), массовый всплеск 100 мс, 5 с модели, один прогон:

| Устройств | Время одного прогона | Окон в датасете |
|---:|---:|---:|
| 1 | ≈ 12–20 с | 10 |
| 10 | ≈ 1,5 мин (90 с) | 10 |
| 30 | ≈ 5 мин (313 с) | 10 |
| 100 | ≈ 11 мин (653 с) | 10 |

Замер 2026-10-24, seed 42, реализация 0, остальное по умолчанию. Время растёт с числом устройств
примерно линейно; 1000 устройств и больше сейчас — часы на прогон (ускорение — этап 2 ROADMAP).
Начинайте с малых нагрузок, проверяйте результат, потом расширяйте.

## 5. Какие параметры можно менять

Все поля — в `src/+nbiot/+config/defaultConfig.m` (там же единицы измерения). Посмотреть текущие
значения: `cfg = nbiot.config.defaultConfig(); cfg.traffic` (и так для любого раздела).

### 5.1. Нагрузка и трафик — меняют чаще всего

| Что | Поле `cfg` | По умолчанию | Простыми словами |
|---|---|---|---|
| Число устройств | `simulation.numUE` | 1000 | Сколько UE в соте. ТЗ §29: 100, 500, 1000, 2500, 5000; для проб — 5–30 |
| Тип трафика | `traffic.kind` | `'burst'` | Когда устройства хотят передавать — см. ниже |
| Начало всплеска | `traffic.burstStartTick` | 1000 | Тик (мс), с которого устройства начинают просыпаться |
| Длительность всплеска | `traffic.burstDurationTicks` | 100 | За сколько мс проснутся все. Короче — больше одновременных попыток, сильнее перегрузка |
| Период | `traffic.periodTicks` | 1000 | Для `'periodic'`: пакет от каждого UE раз в столько мс |
| Интенсивность | `traffic.poissonRatePerSecond` | 0,2 | Для `'poisson'`: в среднем пакетов в секунду на одно UE |
| Размер пакета | `traffic.packetBytes` | 200 | Байт на пакет (ТЗ §30) |
| Очередь | `traffic.queueLimit` | 10 | Сколько пакетов UE держит в очереди; лишние отбрасываются |
| Время жизни пакета | `traffic.lifetimeTicks` | 10000 | Не доставлен за это время — устарел и отброшен |
| Кто активен | `traffic.activityMode`, `traffic.activeUeIds` | `'all'`, `[]` | `'explicit'` + список номеров, например `[1 5 7]`, — трафик только у этих UE |

Типы трафика (ТЗ §11):

| `traffic.kind` | Что происходит | Когда использовать |
|---|---|---|
| `'burst'` | Каждое UE шлёт **один** пакет в случайный момент внутри всплеска | Массовый доступ после аварии — главный сценарий перегрузки |
| `'periodic'` | Каждое UE шлёт пакет раз в `periodTicks` мс (со случайным сдвигом) | Счётчики с регулярными показаниями |
| `'poisson'` | Пакеты в случайные моменты, в среднем `poissonRatePerSecond` в секунду | Случайные события датчиков |
| `'none'` | Пакетов нет | Проверка ложных срабатываний детектора на одном шуме |

Готовые конфигурации есть в `configs/`: `trafficPeriodic()`, `trafficPoisson()`, `baselineStatic()`.
Их можно взять за основу: `cfg = trafficPeriodic(); cfg.simulation.numUE = 20;`.

### 5.2. Управление сетью

| Что | Поле `cfg` | По умолчанию | Простыми словами |
|---|---|---|---|
| Вероятность доступа P | `policy.accessProbability` | 1 | С какой вероятностью UE пытается на очередной возможности. Допустимо 0,1 / 0,25 / 0,5 / 0,75 / 1 |
| Доля ресурсов под RA | `policy.raShare` | 0,1 | 0,1 / 0,2 / 0,3 — то есть RA/DT = 10/90, 20/80, 30/70 |
| Лимит попыток | `ra.maxAttempts` | 8 | После стольких неудач пакет теряется (ТЗ §30) |
| Окно BACKOFF | `ra.backoffTicks` | 256 | После неудачи UE ждёт случайно от 0 до стольких мс |

Без ML-модели P и доля RA постоянны весь прогон — это и есть Static с выбранными значениями. Менять
их полезно и для датасета: адаптивный контроллер будет переключать их на ходу, поэтому модель должна
видеть данные при разных режимах.

### 5.3. Время, случайность, геометрия, канал

| Что | Поле `cfg` | По умолчанию | Простыми словами |
|---|---|---|---|
| Длительность прогона | `simulation.durationTicks` | 5000 | Сколько мс моделировать. Берите кратно 500, чтобы окна были полными |
| «Мир» | `simulation.realizationId` | 0 | Номер случайной расстановки устройств, канала и трафика (0..3999) |
| Зерно | `simulation.seed` | 42 | Общее зерно генератора; обычно не трогают — меняют `realizationId` |
| Радиус соты | `cell.radiusM` | 1000 | Метры. Дальше — слабее сигнал |
| Доля устройств в помещении | `cell.indoorFraction` | 0,3 | В помещении сигнал слабее на 20 дБ (стены) |
| Затухание с расстоянием | `channel.pathLossExponent` | 3,5 | Больше — сигнал быстрее слабеет с расстоянием |
| Мощность передатчика UE | `channel.uePowerDbm` | 23 | дБм (23 дБм ≈ 0,2 Вт) |

**Нельзя менять** (проверка `nbiot.config.validateConfig` остановит запуск с ошибкой `nbiot:config:…`):
шаг 1 мс, частоту дискретизации 1,92 МГц, формат преамбулы и таблицы радиоканалов `cfg.phy.*`. На них
рассчитана физическая модель и откалиброван детектор.

## 6. Как читать результаты

`result = nbiot.runExperiment(cfg)` возвращает struct. Главное в ней:

| Поле | Что это |
|---|---|
| `result.status` | `'completed'` — дошёл до конца; `'failed'` — ошибка (текст в `result.error.message`) |
| `result.kpiSummary` | Итоговые показатели прогона (ТЗ §27) — таблица ниже |
| `result.kpiTimeSeries` | Те же показатели по окнам 500 мс (как менялось во времени) |
| `result.ueSummary` | Таблица по устройствам: где стоит, сколько пакетов создано/доставлено |
| `result.dataset.observations`, `result.dataset.targets` | Признаки и правильные ответы по окнам — основа датасета |

Основные показатели `result.kpiSummary`:

| Поле | Смысл |
|---|---|
| `created`, `delivered`, `dropped` | Пакетов создано, доставлено, потеряно |
| `deliveryProbability` | Доля доставленных пакетов (ТЗ §27.2) |
| `raStarted`, `raSuccess` | Начато попыток доступа (Msg1) и успешных |
| `raSuccessProbability` | Доля успешных попыток доступа (ТЗ §27.1) |
| `collisionAttemptProbability` | Доля попыток, попавших в коллизию (та же частота, что у другого UE) |
| `throughputBitsPerSecond` | Полезных бит в секунду (ТЗ §27.3) |
| `meanDelayTicks` | Средняя задержка доставки, мс |

Таблицы удобно смотреть двойным щелчком в Workspace или командой `head(result.ueSummary)`.
`nbiot.results.saveResult(result, папка)` сохраняет всё в `.mat` (открыть позже: `load(файл)`) и в
CSV-таблицы, которые открываются в Excel или pandas.

## 7. Датасет для обучения (справочник)

### 7.1. Разбиение на train / validation / test

Роль прогона задаётся его номером мира: `realizationId mod 20` (остаток от деления на 20) →
0–13 `train`, 14–16 `validation`, 17–19 `test` (70/15/15). Делятся целые миры, а не отдельные окна:
соседние окна одного прогона похожи, и если их разнести по train и test, модель «подсмотрит» ответ.
Допустимые номера — 0..3999 (4000 и выше заняты калибровкой). **Чтобы были все три роли, берите
хотя бы 20 подряд идущих номеров** (например, `0:19`).

Одинаковый `realizationId` при разных параметрах управления (P, доля RA) — тот же мир: те же
устройства и тот же канал. Так методы сравнивают честно (ТЗ §63).

### 7.2. Опции `collectDataset`

```matlab
summary = nbiot.dataset.collectDataset(cfgs, outputFolder, options);
```

| Опция | По умолчанию | Что делает |
|---|---|---|
| `useParallel` | `false` | `true` — прогоны параллельно на всех ядрах (`parfor`, Parallel Computing Toolbox) |
| `saveRuns` | `true` | Сохранять полный результат каждого прогона в `runs/run_NNNN/` |
| `overwrite` | `false` | Разрешить перезаписать существующий `dataset.csv` |
| `calibrationFile` | `results/nprach-calibration.mat` | Порог детектора преамбул |
| `controllerOptions` | пусто | Для Adaptive-*: оценщик нагрузки (одна struct на все прогоны или cell по прогону) |

Упавший прогон не останавливает сбор: он отмечается в `runs.csv` (`status = "failed"`, текст ошибки)
и не попадает в `dataset.csv`.

### 7.3. Что получится

```
results/my-dataset/
├── dataset.csv        ← все окна всех успешных прогонов (это и есть датасет)
├── runs.csv           ← по строке на прогон: параметры, статус, время, основные KPI
└── runs/run_0001/     ← полный результат прогона (MAT + CSV), если saveRuns = true
```

Столбцы `dataset.csv`:

| Группа | Столбцы | Использование в модели |
|---|---|---|
| Описание прогона | `runIndex`, `policyName`, `numUE`, `trafficKind`, `seed`, `split` | **Не признаки.** Для фильтрации, анализа и разбиения (`split`) |
| Ключи окна | `realizationId`, `windowId`, `startTick`, `endTick` | **Не признаки.** Идентификация окна |
| Признаки BS | `detectedCandidates`, `meanPeakMetric`, `maxPeakMetric`, `meanRxEnergyW`, `ulTbDecodes`, `ulCrcFailures`, `rarSent`, `grantsSent`, `pendingRequestsMean`, `ulRaOccupancy`, `ulDtOccupancy`, `dlRaOccupancy`, `dlDtOccupancy`, `accessProbability`, `raShare` | **Вход модели.** Только то, что станция знает к концу окна (ТЗ §40) |
| Target | `meanRaUe` — основной (среднее число UE в фазе доступа за окно); также `meanActiveUe`, `meanWaitingQueuePerUe`, `msg1Transmissions`, `uniqueMsg1Ue` | **Только как ответ.** Это истина симулятора — в признаки нельзя (ТЗ §40) |

Точный список признаков с единицами — `nbiot.dataset.featureSchema()` (поля `inputNames`, `units`).
Модель в контроллере получит ровно `inputNames` в этом порядке — обучайте на них же.

**Почему `numUE` — не признак.** Станция не знает, сколько устройств конкурирует; оценить это по
наблюдениям и есть задача модели. Столбец нужен только для анализа (например, ошибка по уровням нагрузки).

### 7.4. В Python

```python
import pandas as pd
df = pd.read_csv("results/my-dataset/dataset.csv")
features = ["detectedCandidates", "meanPeakMetric", "maxPeakMetric", "meanRxEnergyW",
            "ulTbDecodes", "ulCrcFailures", "rarSent", "grantsSent", "pendingRequestsMean",
            "ulRaOccupancy", "ulDtOccupancy", "dlRaOccupancy", "dlDtOccupancy",
            "accessProbability", "raShare"]
train, val, test = (df[df.split == s] for s in ("train", "validation", "test"))
X_train, y_train = train[features], train["meanRaUe"]
```

Несколько датасетов (разные сценарии) объединяются склейкой CSV. Один и тот же `realizationId` с
другими параметрами — тот же мир, он автоматически попадёт в ту же выборку.

### 7.5. Без `collectDataset`

Можно писать свой код вокруг ядра: `result = nbiot.runExperiment(cfg)`, дальше
`result.dataset.observations` и `result.dataset.targets` (таблицы с одинаковыми ключами окон) и
`nbiot.results.saveResult(result, папка)`.

## 8. Частые ошибки и вопросы

| Сообщение / ситуация | Причина и что делать |
|---|---|
| `Unrecognized function or variable 'startupProject'` (или `'nbiot'`) | Текущая папка — не корень проекта, или не выполнен `startupProject()`. В скрипте — начните с двух строк из §4; в Command Window — перейдите в корень и выполните `startupProject()` |
| `nbiot:phy:Calibration` | Не загружена калибровка. Добавьте строку `cfg = nbiot.phy.nprach.loadCalibration(cfg, …)` (§4.1) или используйте `collectDataset` |
| `nbiot:config:…` | Недопустимое значение параметра; в тексте ошибки — какое поле. Сверьтесь с §5 |
| LTE Toolbox не найден | Установите дополнение: Home → Add-Ons → LTE Toolbox |
| `result.status` = `'failed'` | Текст ошибки — `result.error.message` |
| Прогон идёт очень долго | Нормально для сотен UE (§4.4). Ctrl+C прерывает. Начните с 5–10 UE |
| В датасете нет validation/test | Номера миров не покрыли остатки 14–19 от деления на 20 — берите `0:19` |
| Последнее окно короче остальных | `durationTicks` не кратно 500 |
| Хочу Adaptive-P / Adaptive-RA/DT | Нужен оценщик нагрузки (обученная модель) в `controllerOptions`: `struct('estimator', @(features) …)`. Для первого датасета хватает Static с разными P и долями RA |
| Изменил параметры преамбулы | Нужна перекалибровка `examples/calibrateNprach.m` (долго); обычно эти параметры не трогают |

## 9. Словарь терминов

| Термин | Значение |
|---|---|
| **UE** (User Equipment) | Устройство: счётчик, датчик |
| **BS** (Base Station, eNB) | Базовая станция — центр соты |
| **Сота** | Зона, которую обслуживает одна BS; у нас круг радиусом 1 км |
| **UL / DL** (uplink / downlink) | Направление: от устройства к станции / от станции к устройству |
| **RA** (Random Access) | Случайный доступ — процедура «постучаться» к станции (Msg1–Msg4) |
| **NPRACH** | Канал, по которому устройство шлёт преамбулу (Msg1) |
| **Преамбула** | Короткий сигнал «я здесь» на одной из 12 частот (номер частоты — `nInit`) |
| **Возможность NPRACH** | Момент, когда разрешено слать преамбулы; у нас каждые 80 мс |
| **RAR** (Msg2) | Ответ станции на услышанную преамбулу |
| **Msg3 / Msg4** | «Я — устройство X» / «устройство X, доступ разрешён» |
| **Коллизия** | Два и больше UE выбрали одну частоту на одной возможности |
| **Capture** | При коллизии сильный сигнал всё же прошёл, слабый — нет |
| **BACKOFF** | Случайное ожидание перед повторной попыткой |
| **DT** (Data Transmission) | Передача данных после успешного доступа |
| **RA/DT = 10/90** | Доли ресурсов под доступ и под данные |
| **P** (access probability) | Вероятность, с которой UE пытается на очередной возможности |
| **NPUSCH / NPDCCH / NPDSCH** | Каналы: данные UL / управляющие команды DL / данные DL |
| **CRC** | Контрольная сумма: по ней приёмник понимает, что данные пришли без ошибок |
| **HARQ** | Повторная передача блока, не прошедшего CRC (до 4 раз) |
| **Waveform** | Сам радиосигнал (массив отсчётов); модель считает на его уровне |
| **SINR, дБ** | Насколько полезный сигнал сильнее помех и шума |
| **Тик** | Шаг модели = 1 мс |
| **Окно** | 500 мс; одна строка датасета |
| **Реализация, «мир»** (`realizationId`) | Номер случайной расстановки устройств, канала и трафика |
| **KPI** | Ключевые показатели: доля доставки, успех доступа, задержка, пропускная способность |
| **Признак / target** | Вход модели (то, что видит станция) / правильный ответ (истинная нагрузка) |
| **Static / Adaptive-P / Adaptive-RA/DT** | Сравниваемые методы управления (§1) |
