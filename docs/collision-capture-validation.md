## Параметры ядра до появления GUI

Матрица отражает текущую проверку `validateConfig`; фиксированные ограничения PHY-профиля остаются явными. Положительное значение в столбце «Ввод» означает, что конфигурация принимается валидатором, но изменение физического параметра ещё требует своей физической приёмки.

| Группа | Принимаемый ввод | Проверка/ограничение |
|---|---|---|
| Горизонт и нагрузка | `numUE` — целое 1–65535; `durationTicks` — 1–2²⁴−1; `seed` — 0–2³²−1; `realizationId` — 0–4095 | `tickSeconds=0.001` и `sampleRateHz=1.92 MHz` фиксированы |
| Геометрия | Радиус положительный и больше `minDistanceM`; минимум и высоты неотрицательны; `indoorFraction` ∈ [0,1]; `cellId` — 0–503 | Поддержано; аналитические границы проверяет collision test |
| Канал и мощность | Несущая, опорная дистанция, показатель потерь и температура положительны; shadowing, penetration, CFO и sync limits неотрицательны; мощности и noise figure конечны | Задержки taps отсортированы и неотрицательны; мощности taps конечны и совпадают по числу; длина fractional filter — нечётная 3–4095. Новый профиль требует отдельной физической проверки |
| Трафик и очередь | `kind` ∈ {burst, periodic, poisson, none}; пакет — 1–6630 байт; очередь — 1–65535; интервалы положительные целые; burst start неотрицателен; Poisson rate неотрицателен | Проверяется `validateConfig`; физические опыты Stage 2 используют короткий burst для постановки коллизии |
| Доступ | Попытки, период, число поднесущих, RAR/Contention PP — положительные целые; backoff и start offset имеют целочисленные границы | Текущий профиль фиксирует format 0, одну репетицию и 12 поднесущих; NPRACH occurrence должна помещаться в период |
| Политика и окна | P и RA share ∈ [0,1]; policy/dataset window — положительное целое число ms | Сейчас поддержана только политика `Static`; шаг расчёта остаётся 1 ms |
| PHY и экспорт | Калиброванный threshold ∈ (0,1] либо `NaN` до калибровки; CFO grid конечна и непуста; идентификаторы sample rate/cell должны совпадать; выходной путь — непустой | Таблицы PHY-профиля должны совпадать с static-v1; неподдерживаемые профили отклоняются |

Наличие валидатора не означает, что любая принятая комбинация уже получила физическую валидацию. Изменение частоты, taps, мощности, временных искажений или профиля канала включается в отдельный сохранённый набор опытов до использования в сравнительной серии.

## Исправление сопоставления CRC

Планировщик назначает NPDSCH с RAR временному RA-RNTI. UE получает C-RNTI только после успешного декодирования RAR и отправки Msg3. Анализатор ранее искал CRC RAR по C-RNTI, поэтому не находил корректную запись в `truthLog`. Теперь трасса каждого доступа сохраняет фактический RA-RNTI; RAR сопоставляется по нему, а Msg3 и Msg4 — по C-RNTI. Проверка остаётся только в диагностическом анализаторе и не меняет работу симулятора.

## Команды для ПК с MATLAB R2025b

Откройте PowerShell в корне `github-v2-publication` и сначала выполните целевой набор, сохранив фактический лог:

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss-fff'
$targetedLog = "verification/completion/stage-2/targeted-r2025b-$stamp.log"
matlab -batch "run('verification/completion/stage-2/stage2Targeted.m')" 2>&1 | Tee-Object -FilePath $targetedLog
if ($LASTEXITCODE -ne 0) { throw 'Stage 2 targeted tests failed.' }
```

После успешного целевого набора запустите ограниченную физическую серию Stage 2:

```powershell
matlab -batch "run('verification/completion/stage-2/stage2Physical.m')"
```

Второй скрипт сохраняет уникальные `.log`, `.mat` и CSV-файлы в `verification/completion/stage-2/physical-<timestamp>`. В нём задан верхний предел 10 независимых ID на условие. Он не запускает массовую сравнительную серию Stage 7.

После просмотра сводок, интервалов, ложных обнаружений/пропусков и известных ограничений оператор может записать факт приёмки. Подставьте реальный каталог физического запуска:

```powershell
matlab -batch "addpath('verification/completion/stage-2'); acceptStage2Evidence('$targetedLog','verification/completion/stage-2/physical-<timestamp>/stage2-report.mat',true,'Кратко зафиксировать рассмотренные результаты и ограничения.')"
```

Функция требует 35/35 целевых тестов collision/receiver/acceptance/registry/pilot, 150 опытов с десятью уникальными ID на условие, хотя бы одну CRC-подтверждённую цепочку в совокупности десяти different-preamble контрольных опытов, 80 receiver checks с указанными критериями, точного соответствия измеренных ID завершённым ролям реестра, исходных хешей кода и неизменного реестра. Параметр `true` — явное подтверждение человека, что физические результаты и ограничения просмотрены; `reviewNotes` должны кратко описывать просмотренные ограничения. Файл фиксирует хеши доказательств. Только после этого разрешён полный bounded Stage 3 pilot из `docs/experiment-budget.md`.
