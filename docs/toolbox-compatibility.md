# LTE Toolbox compatibility and target-PC acceptance

## Current candidate evidence (2026-10-06)

MATLAB R2025b and LTE Toolbox execute on this PC. The initial offline notes below are historical. Current algorithms/tests and finite acceptance bounds are in [performance-report.md](performance-report.md). NPRACH presence uses all-tone group partial quadratic regression and a new calibrated threshold; FFT/SIC estimates parameters only. DL uses CP/NRS coarse timing, FreqWindow1/TimeWindow1 and a received-pilot residual noise estimate. The old statement about unexecuted FreqWindow25 does not describe this candidate. GPU support was measured separately; CPU remains the production backend.

## Historical API design notes

Source was written offline on 2026-10-04. MATLAB was unavailable. No API execution, waveform roundtrip, CRC result, numerical acceptance, calibration threshold or BLER result is claimed.

Target profile: MATLAB R2025b, LTE Toolbox, Release-13 standalone FDD, one antenna, Fs=1.92 MHz. Run `addpath('src','examples'); report=checkEnvironment(true)` on the target PC. The script records release, Toolbox version, resolved API paths and performs actual waveform roundtrips for NPUSCH Data, NPUSCH Control, NPDCCH and NPDSCH. Missing functions produce `nbiot:phy:MissingToolbox`; unexpected shapes or incomplete bundles fail assertions. No synthetic PHY fallback exists.

UL follows the [MathWorks NPUSCH example](https://www.mathworks.com/help/lte/ug/nb-iot-npusch-block-error-rate-simulation.html): NULSCH coding, slot-wise NPUSCH and DRS mapping, SC-FDMA, received DRS channel estimation, equalization inside NPUSCHDecode and NULSCHDecode. CRC output zero is success; decoder soft buffers persist across unchanged NDI. Control carries decoded one-bit UCI and no CRC. DMRS coherence supplies a conservative presence gate with default 0.5; this research gate needs independent noise, interference and fading validation.

NB-IoT DL OFDM uses the [MathWorks NPDSCH example's narrowband modulator](https://www.mathworks.com/help/lte/ug/nb-iot-npdsch-block-error-rate-simulation.html): `lteSCFDMAModulate` and `lteSCFDMADemodulate` with NBULSubcarrierSpacing=15kHz operate on already precoded DL grids and supply the required half-subcarrier shift. There is no UL DFT precoding stage in the DL adapter. NRS is generated with LTE Toolbox and received NRS estimates drive `lteDLChannelEstimate` with Reference=NRS. NPDSCH uses NDLSCH transport coding and actual CRC. NPDCCH uses [lteDCIEncode](https://www.mathworks.com/help/lte/ref/ltedciencode.html) with explicit capacity and [lteDCIDecode](https://www.mathworks.com/help/lte/ref/ltedcidecode.html) with 23-bit payload size; recovered CRC RNTI must equal the monitored RNTI.

The public [NPRACH API](https://www.mathworks.com/help/lte/ref/ltenprach.html) returns a whole periodic buffer. The adapter disables windowing, cuts the known 8ms start padding and retains exactly the format-0 CP/symbol duration 5.6ms; only this active signal contributes to power. Twelve cached templates are correlated against all CFO hypotheses and all permitted timing offsets. No receiver accepts a list of transmitting UE.

Tables and layouts are transcribed from [ETSI TS36.213 Release13](https://www.etsi.org/deliver/etsi_ts/136200_136299/136213/13.13.00_60/ts_136213v131300p.pdf), sections16.3.3,16.4,16.5, and [ETSI TS36.212 Release13](https://www.etsi.org/deliver/etsi_ts/136200_136299/136212/13.03.00_60/ts_136212v130300p.pdf), section6.4.3. Reserved table entries raise errors. RAR subcarrier indication uses the same table as N0:12 means three tones0:2; RAR MCS2 selects NRU1/TBS88 and is distinct from ordinary MCS6.

After environment checks, run `calibrateNprach` for 20,000 independent fit windows and at least 20,000 fresh validation windows. Store the saved threshold into cfg.phy.nprachThreshold. The saved report contains a two-sided exact95% binomial interval and rejects an upper bound above0.001. It explicitly does not claim interference acceptance. Default threshold NaN deliberately prevents a simulation using an uncalibrated receiver.

NPRACH delay and CFO estimates refine interior bank maxima with three-point parabolic interpolation bounded to half a search step. Acceptance metrics remain the searched-grid peaks used during calibration. Calibration reports include the exact public profile fields, realization IDs, CFO grid, release and Toolbox version. Practical estimators use nontrivial pilot averaging to estimate noise: UL frequency window23, DL frequency window25, and a three-symbol Control DM-RS time window. Their behavior on short received grids remains unexecuted.

UL timing uses [lteULFrameOffsetNPUSCH](https://www.mathworks.com/help/lte/ref/lteulframeoffsetnpusch.html) on the received first slot and its sample margins. Its DM-RS correlation is searched within the available margin, bounded by64 samples each way by default (optional cfg.phy.ulTimingSearchSamples, maximum128). The complete bundle is extracted at the resulting received timing estimate before pilot CFO estimation. Measurements include delaySamples,delaySeconds,correlationPeak,peakToMean and the searched interval. There are no true propagation-delay inputs. A target-PC acceptance check adds11 waveform samples and checks the decoded CRC and received timing estimate.

Unexecuted acceptance risks: release-specific state initialization and argument handling; slot/subframe waveform sizes with Windowing=0; practical channel estimation on one slot/subframe; DM-RS timing and CFO under collisions/deep fades; ACK presence threshold under interference; SIB1 encoder phase at a simulation horizon starting mid-bundle. Numeric acceptance must include fractional delays and TA error within the configured range. Fixed bootstrap MIB/SIB1 bits are research payloads, not complete ASN.1 RRC system information.
