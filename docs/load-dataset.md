# Сборка данных оценки нагрузки

Реализована базовая обработка сохранённых данных, 13 октября 2026. Расчёты сети и обучение при сборке не запускаются.

## Входы и выходы

`nbiot.dataset.assembleLoadDataset(resultFiles, splitManifest)` принимает явный список MAT-файлов manifested cases и таблицу с `externalRealizationId`, `split` и, для новых наборов, отдельной `experimentRole`. `split` показывает часть для машинного обучения, а `experimentRole` — назначение опыта в исследовании. У одного ID одна группа и одна роль во всех нагрузках и методах; повторные ID в manifest отклоняются.

Допустимые группы `split`: `development`, `train`, `validation`, `test`. Роль `experimentRole` задаётся отдельно: `development`, `training`, `validation`, `model-test` или `final-comparison`. Проверяется соответствие: development→development, train→training, validation→validation; test допускает model-test или final-comparison. Таким образом, финальное сравнение может входить в отдельную часть `test`, но его роль не путается с обычной проверкой модели.

Старый manifest только с двумя столбцами остаётся доступен: сборщик выводит роль из `split` и записывает `experimentRolesExplicit=false`. Это совместимость со старыми development-данными, а не доказательство назначенной роли; такой manifest нельзя использовать для training-сборки.

Проверяются completed-marker, файлы/размеры/SHA-256, MAT-снимки, схемы и CSV. Читаются снимки и таблицы, без загрузки большого `result` в память. Работа с большими архивами всё равно требует времени на проверку целостности; используйте внешнюю обвязку 300 секунд.

Ключ строки: `caseKey + realizationId + windowId + startTick + endTick`. Ответы сортируются/сопоставляются по ключу, а не по порядку строк CSV. Все закрытые окна завершённого горизонта должны присутствовать; дубликаты, пропуски, чужие ID, незавершённые случаи и несовместимые версии отклоняются.

Результат содержит:

- `observations` — ключи и наблюдения базовой станции;
- `features` — только признаки базовой станции, без ID/времени/ответов;
- `targets` — отдельно `meanRaUe` и диагностические ответы;
- `rowInfo` — caseKey, ключи окон, split и роль опыта;
- `schema` и `manifest` — версия, происхождение, хеши маркеров, число независимых ID, распределение групп и явность ролей. Для каждого сохранённого случая manifest также фиксирует тип трафика и его рабочие параметры, а также исходные настройки доступа P и доли RA.

Основной ответ: `meanRaUe`, среднее число устройств в процедуре доступа за окно; это не вход модели. Текущая схема `bs-known-v2.0` содержит 15 входных признаков: девять старых наблюдений, четыре доли занятых UL/DL-ресурсов отдельно для RA и DT, а также вероятность доступа `accessProbability` и долю RA `raShare`, действовавшие в закрытом окне. Занятость считается только по зарезервированным ресурсам этого окна; настройки окна не берутся из будущего. Если значение недоступно, сохраняется `NaN`, а не ноль. Заполнение пропусков и преобразования обучаются только по train.

Старые таблицы схемы `static-v1.0` с девятью входными признаками остаются доступны для чтения. Их нельзя смешивать с `bs-known-v2.0` или использовать для обучения текущей модели; отсутствующие новые столбцы не дополняются придуманными нулями. Сохранённый пилот ниже — именно старый набор `static-v1.0`.

Новые manifested MAT сохраняют маленький `datasetSchema` snapshot. Прежние v2 cases без такого snapshot читаются по строгой известной Static-схеме CSV. Источник вычислений и калибровка внутри одного набора должны совпадать. Синтетические тестовые пакеты помечаются `development-fixture` и запрещены для научного training build.

## Сохранение набора

```matlab
setupProject();
splitManifest=table(1064,"development","development", ...
    'VariableNames',{'externalRealizationId','split','experimentRole'});
options=struct('resultFiles',{resultFiles},'splitManifest',splitManifest, ...
    'outputFolder',fullfile(pwd,'results','datasets','new-development-set'),'purpose','development');
data=buildLoadDataset(options);
```

`resultFiles` — заранее выбранный список сохранённых MAT, а не поиск новых сценариев. Непустой выходной каталог не перезаписывается. Сохраняются `dataset.mat`, observations/targets/features/rows CSV и `manifest.json`.

Также создаются `dataset-summary.json` и `scenario-coverage.csv`. В сводке указаны версия схемы, признаки и ответ модели, число строк/случаев/независимых ID, распределение ID по группам и ролям, а также покрытие типов трафика, числа UE и настроек P/RA. CSV показывает один сохранённый случай на строку: тип трафика и нужный для него параметр (burst, период или интенсивность Poisson), настроенный P/RA и значения P/RA, реально записанные по закрытым окнам. Пустые значения означают, что старая схема не сохраняла этот показатель. Количество окон не считается количеством независимых реализаций. Отчёт описывает только переданные файлы и сам по себе не доказывает полноту научной выборки.

Служебная сборка не меняет реестр ID и исходные результаты.

Для `purpose='training'` требуются явная роль каждого ID и `registryFile`. Builder проверяет, что в реестре есть завершённое выделение ID с той же ролью; незаконченные и диагностические выделения, старые зарезервированные ID и development-fixtures не проходят. Роль `final-comparison` всегда запрещена и сборщиком, и самой функцией обучения, чтобы итоговые сравнительные результаты не попадали в подбор модели. Чистая функция `assembleLoadDataset` проверяет назначение и совместимость роли с группой, но не подтверждает реестр: `allocationsVerified=false`, пока builder не выполнит эту проверку. Подробнее — в [описании проверки моделей](ml-validation.md).

В окне можно выгрузить development-набор из одного завершённого сохранённого запуска: нажать **Экспортировать development-набор** и выбрать папку. Интерфейс проверяет manifested case и местные пределы (до 10 UE и 5000 мс), явно назначает этому ID группу и роль `development`, затем вызывает тот же сборщик. Это удобный пример для отладки, а не вход для `purpose='training'` и не подтверждение качества модели.

Это материал для разработки конвейера, не раздельная обучающая/test выборка и не доказательство точности на больших нагрузках. Новые независимые данные и проверка области применимости модели остаются работой другой машины.

Доказательства тестов и выполнения: `verification/local/final-task12/`, `verification/local/saved-pilot-assembly/`, `verification/local/dataset-role-separation-final-20261013.log`.
